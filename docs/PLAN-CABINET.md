## 1. Цель

Сайт должен продавать видеопрограммы Лили людям, которые приходят из Instagram (подписчики Лили и реклама), и давать покупателю личный кабинет с видео.

1. Видео разбиты на категории. Продаётся доступ к категории (и набор «все категории»).
2. Оплата через Stripe аккаунта Restore Lab (аккаунт Михаила).
3. Покупатель после оплаты сразу попадает в кабинет и смотрит видео. Повторный вход по коду из письма.
4. Персональное сопровождение (тарифы, кнопка в Telegram) остаётся на сайте как второй, дорогой продукт.

Цены, список категорий и сами видео Михаил даст позже. Всё, что от них зависит, делается на тестовых данных и меняется в одном файле `content/catalog.json`.

## 4. Структура сайта

### 4.1. Публичная часть (продажа)

| Адрес | Назначение |
|---|---|
| `/` и `/en/` | Главная. Порядок блоков: первый экран (оффер, цена «от», кнопка к программам, вертикальное видео), доверие (цифры, сертификаты), программы (карточки категорий с ценой), как устроен кабинет (3 шага: оплата, вход, видео), результаты, бесплатный урок за email, персональное сопровождение (текущие тарифы, кнопка в Telegram), FAQ, футер с юридическими ссылками |
| `/links/` | Страница для ссылки в шапке Instagram. 4 кнопки: бесплатный урок, программы, сопровождение, Telegram-канал. Грузится мгновенно, без видео |
| `/programs/` | Каталог категорий |
| `/programs/<slug>/` | Продающая страница категории: для кого, что внутри (список видео с длительностью, закрытые с замком), бесплатное превью-видео без входа, цена, кнопка «Купить», FAQ |
| `/free/` | Лид-магнит: бесплатная категория (1–3 видео) в обмен на email. Регистрация по коду и есть сбор лида |
| `/login/` | Вход по email и коду |
| `/account/` | Кабинет (см. 4.2) |
| `/checkout/success/`, `/checkout/cancel/` | Возврат из Stripe |
| `/legal/terms/`, `/legal/privacy/`, `/legal/refunds/` | Оферта, политика данных, возвраты. Тексты даёт юрист, до этого страницы-заглушки с пометкой в чек-листе запуска |
| `/404.html` | Настоящая 404 (сейчас любой адрес отдаёт главную) |

Адреса `/workouts/...` из июньской работы заменить на `/programs/...`.

Требования к продающим страницам (трафик из Instagram почти весь с телефона и открывается во встроенном браузере Instagram):
- Сначала телефон, ширина 360–390. Правило Михаила: один смысловой блок = один экран (бюджет высоты 660 px при 390 и 640 px при 360).
- На первом экране видны оффер, цена и кнопка.
- До оплаты не требовать регистрацию: кнопка «Купить» спрашивает только email и сразу ведёт в Stripe Checkout.
- Промокоды Stripe включены (`allow_promotion_codes`), чтобы давать коды в сторис.
- UTM-метки сохраняются при первом заходе и уходят в лид, заказ и метаданные Stripe. Формат: `utm_source=instagram`, `utm_medium=bio|stories|reels|ads`, `utm_campaign=<название>`.
- Только существующая дизайн-система и реальные фото и видео Лили. Без новых декоративных приёмов (сетки точек, «таблетки», сетки иконок, плашки-уведомления).
- Новые тексты на «ты», в женском роде, без длинных тире. Все новые тексты считаются черновиком до согласования с Лилей.

### 4.2. Кабинет `/account/`

Один HTML-файл и ванильный JS, данные через `/api/*`.

1. «Мои программы»: купленные категории открыты, остальные показаны закрытыми с ценой и кнопкой «Купить».
2. Категория: список видео, отметка просмотренного, продолжить с места остановки.
3. Просмотр: плеер, описание, следующее видео.
4. Профиль: email, покупки со ссылкой на чек Stripe, выход, кнопка «Написать Лиле».

Правило доступа к видео: видео доступно, если это превью, или категория бесплатная и пользователь вошёл, или у пользователя активное право на категорию, или активное право «все категории».

### 4.3. Админка `/admin/`

Вход только для email из переменной `ADMIN_EMAILS`. Список пользователей и прав, выдать или отозвать доступ вручную, выгрузка лидов и покупателей в CSV. Видео загружаются в кабинете видеохостинга, каталог правится в `content/catalog.json`.

## 5. Архитектура

Сайт остаётся статическим. Серверная часть на Cloudflare Pages Functions, чтобы всё жило в одном проекте и одном домене.

```
/src                    статика (как сейчас) + новые страницы
/functions/api/...      Pages Functions (TypeScript)
/content/catalog.json   категории, видео, цены (источник правды)
/migrations/*.sql       схема D1
/tests                  vitest
wrangler.toml, package.json
```

- База: Cloudflare D1.
- Секреты только через `wrangler secret` и переменные проекта. В репозитории ни одного ключа и ни одной ссылки доступа.
- Cloudflare Pages: каталог сборки `src`, функции в `/functions`. У каждой ветки есть адрес предпросмотра, на нём идут все проверки до слияния.

### 5.1. Каталог `content/catalog.json`

```json
{
  "categories": [
    {
      "slug": "spina",
      "title": { "ru": "Спина без боли", "en": "Back without pain" },
      "free": false,
      "published": true,
      "price": { "amount": 3900, "currency": "eur" },
      "stripePriceId": "price_...",
      "videos": [
        { "id": "spina-01", "title": { "ru": "...", "en": "..." },
          "durationSec": 900, "preview": true,
          "provider": "stream", "providerVideoId": "..." }
      ]
    }
  ],
  "bundles": [
    { "slug": "all", "categories": "*", "price": { "amount": 9900, "currency": "eur" }, "stripePriceId": "price_..." }
  ]
}
```

Публичный `/api/catalog` отдаёт каталог без `providerVideoId`. Числа в примере условные.

### 5.2. Таблицы D1

| Таблица | Поля |
|---|---|
| `users` | id, email (уникальный, в нижнем регистре), locale, marketing_consent, utm_source, utm_medium, utm_campaign, created_at |
| `login_codes` | email, code_hash, expires_at, attempts, created_at |
| `sessions` | id_hash, user_id, expires_at, created_at |
| `orders` | id, user_id, email, stripe_session_id (уникальный), stripe_payment_intent, amount, currency, items, status, utm, created_at |
| `entitlements` | id, user_id, scope (slug категории или `all`), source (`stripe`, `manual`, `free`), order_id, status (`active`, `revoked`), expires_at (null = навсегда), created_at |
| `stripe_events` | event_id (уникальный), type, received_at |
| `progress` | user_id, video_id, seconds, completed, updated_at |

### 5.3. API

| Метод и адрес | Что делает |
|---|---|
| `POST /api/auth/request-code` | Письмо с кодом. Всегда отвечает одинаково. Лимит по email и IP, Turnstile |
| `POST /api/auth/verify-code` | Проверяет код (5 попыток, 10 минут), создаёт пользователя при первом входе, ставит cookie сессии (HttpOnly, Secure, SameSite=Lax, 30 дней) |
| `POST /api/auth/logout` | Удаляет сессию |
| `GET /api/me` | Пользователь и его права |
| `GET /api/catalog` | Публичный каталог |
| `POST /api/leads` | Email + согласие + UTM для `/free/`: создаёт пользователя, право `free`, шлёт код |
| `POST /api/checkout` | Создаёт Stripe Checkout Session: `client_reference_id`, `customer_email`, `metadata: { brand: "lily", scope, utm }`, `allow_promotion_codes: true`, адреса возврата |
| `GET /api/checkout/complete?session_id=` | Проверяет в Stripe, что сессия оплачена, создаёт пользователя и право (если вебхук ещё не успел), ставит cookie и ведёт в `/account/` |
| `POST /api/stripe/webhook` | Проверка подписи. `checkout.session.completed` и `checkout.session.async_payment_succeeded` создают заказ и право. `charge.refunded` отзывает право |
| `GET /api/videos/:id/playback` | Проверяет право, отдаёт подписанный токен плеера на 2 часа |
| `POST /api/progress` | Сохраняет прогресс |
| `GET/POST /api/admin/*` | Пользователи, выдача и отзыв прав, CSV |

Обязательные правила:
1. Аккаунт Stripe общий с Restore Lab. Вебхук обрабатывает только сессии с `metadata.brand === "lily"`, остальные пропускает с ответом 200.
2. Вебхук идемпотентен: событие с уже записанным `event_id` не обрабатывается второй раз. `stripe_session_id` в заказах уникален.
3. Права создаются только из вебхука, из `checkout/complete` после проверки в Stripe или из админки. Никогда по параметрам из браузера.
4. Ссылки и идентификаторы видео для закрытых видео не попадают в публичные файлы.
5. До чек-листа запуска только тестовый режим Stripe и тестовые карты. Боевые ключи ставит Михаил.

### 5.4. Путь покупателя из Instagram

1. Сторис или шапка профиля, переход на `/links/` или сразу на `/programs/<slug>/?utm_...`.
2. Превью-видео, кнопка «Купить», ввод email.
3. Stripe Checkout (карта, Apple Pay, Google Pay, промокод).
4. Возврат на `/api/checkout/complete`, cookie, кабинет с открытой категорией.
5. Письмо: «доступ открыт» и как войти с другого устройства (email + код). Cookie встроенного браузера Instagram не видны в Safari и Chrome, поэтому это письмо обязательно.

Путь лида: `/free/`, email, код, бесплатная категория в кабинете, рядом закрытые платные категории с ценой.

### 5.5. События аналитики

`page_view`, `lead_submit`, `login_code_sent`, `login_success`, `preview_play`, `checkout_start`, `purchase` (с сервера, из вебхука), `video_start`, `video_complete`. У каждого события UTM и slug категории.

### Этап 2. Сервер и вход

Статус: КОД ГОТОВ 24.11.2026, ждёт проверки Михаила на iPhone и Android во встроенном браузере Instagram.
- `wrangler.toml` стал источником правды для привязок: верхний уровень = предпросмотр и локальная разработка, `[env.production]` = lily.coach. Созданы D1 `lily-coach-preview` (миграция 0001 применена) и `lily-coach` (боевая, пустая, миграции на этапе 7).
- Миграция `0001_auth.sql`: `users`, `login_codes` (один код на email), `sessions` (SHA-256 токена), `entitlements`, `rate_limits`. Время в секундах Unix.
- Код: 6 цифр, в базе HMAC-SHA256 с секретом `AUTH_SECRET`, живёт 10 минут, 5 попыток, после входа удаляется. Лимиты: 5 кодов в час на email, 20 запросов кода и 60 проверок в час на IP. Пользователь создаётся только при верном коде, поэтому ответ на запрос кода не зависит от того, есть ли аккаунт.
- Cookie `lily_session`: HttpOnly, Secure, SameSite=Lax, Path=/, 30 дней. `GET /api/me` гостю отвечает 200 `{ user: null, entitlements: [] }`, чтобы в консоли не было 401.
- Все POST в `/api/*` только с Origin своего сайта (иначе 403), ответы `no-store`, неизвестный `/api/*` отдаёт JSON 404. Добавлен `GET /api/auth/config` (публичный ключ Turnstile).
- Turnstile: виджет «lily.coach login» (managed, домены lily.coach и lily-smart-fitness.pages.dev, поддомены входят) создан через `wrangler turnstile`. Без `TURNSTILE_SECRET_KEY` проверка пропускается (локально и в тестах).
- Письма: Resend, `Lily <hello@lily.coach>`, тема «Код для входа: 123456», ссылка на Telegram Лили, без Reply-To. Локально код пишется в лог wrangler.
- Секреты Preview: `AUTH_SECRET`, `TURNSTILE_SECRET_KEY` добавлены, `RESEND_API_KEY` был. В Production пока только `RESEND_API_KEY`.
- `/login/`: email, код (6 цифр, автоотправка, `autocomplete="one-time-code"`), повторная отправка через 60 с, «Другой email», состояние «Ты вошла» с выходом, `?next=/путь` после входа, шаг с кодом переживает перезагрузку (sessionStorage, 10 минут). Тексты в словаре `I18N` в `js/login.js`, черновик до согласования с Лилей.
